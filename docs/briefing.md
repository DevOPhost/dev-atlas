## Internacionalização

O site deve ter suporte a versões em mais de um idioma.

Idiomas desejados inicialmente:

* Português do Brasil
* Inglês
* Espanhol

A estrutura do projeto deve permitir adicionar novos idiomas no futuro sem precisar refazer o site.

Inclua:

* Seletor de idioma visível no header ou menu.
* URLs organizadas por idioma, como `/pt`, `/en` e `/es`.
* Tradução de menus, botões, títulos, descrições, cards, páginas e mensagens do sistema.
* Conteúdo preparado para tradução.
* Estrutura escalável para arquivos de tradução.
* Detecção opcional do idioma do navegador.
* Possibilidade de manter o idioma escolhido pelo usuário.
* SEO separado por idioma.
* Meta tags específicas para cada versão.
* Uso correto de `hreflang`.
* Cuidado para que textos longos em outros idiomas não quebrem o layout.

Sugira a melhor abordagem técnica para internacionalização, considerando uma stack moderna como:

* Next.js
* TypeScript
* Tailwind CSS
* Shadcn/ui
* next-intl ou outra biblioteca adequada
* Conteúdo em JSON, Markdown ou MDX

Explique como organizar os arquivos de idioma e como estruturar o conteúdo multilíngue.

## Acessibilidade

O site deve seguir boas práticas de acessibilidade para que seja utilizável por diferentes tipos de usuários.

Inclua recursos como:

* HTML semântico.
* Boa hierarquia de títulos.
* Contraste adequado entre texto e fundo.
* Navegação por teclado.
* Estados visuais claros de foco.
* Textos alternativos em imagens.
* Botões e links com nomes acessíveis.
* Formulários com labels corretos.
* Componentes compatíveis com leitores de tela.
* Uso adequado de ARIA apenas quando necessário.
* Tamanho de fonte confortável.
* Espaçamento adequado.
* Modo claro e modo escuro acessíveis.
* Evitar animações excessivas.
* Opção para reduzir animações, respeitando `prefers-reduced-motion`.
* Evitar depender apenas de cores para transmitir informações.
* Mensagens de erro claras.
* Layout responsivo e legível em celulares.
* Componentes testados com ferramentas como Lighthouse, axe DevTools ou similares.

O site deve ser pensado para atender, sempre que possível, às recomendações da WCAG.

## Interface e experiência do usuário

A interface deve ser muito intuitiva, bonita, moderna e agradável de usar.

Mesmo sendo um site com muito conteúdo, o usuário não pode se sentir perdido. A navegação precisa ajudar a pessoa a entender onde está, para onde pode ir e qual caminho seguir.

A interface deve ter:

* Visual moderno e limpo.
* Layout responsivo.
* Header organizado.
* Menu claro por categorias.
* Busca global.
* Filtros por área, nível, tecnologia e tipo de conteúdo.
* Cards bem organizados.
* Tags visuais.
* Breadcrumbs.
* Navegação lateral em páginas longas.
* Botão de voltar ao topo.
* Roadmaps visuais.
* Comparações em tabelas bem legíveis.
* Seções com boa hierarquia visual.
* Microinterações suaves.
* Animações discretas e profissionais.
* Modo claro e escuro.
* Ícones consistentes.
* Páginas internas confortáveis para leitura.
* Chamadas visuais para orientar iniciantes.
* Seção “Não sabe por onde começar?”.
* Quiz ou guia interativo para escolher uma área de TI.
* Página de favoritos ou conteúdos salvos, se fizer sentido.
* Indicadores de nível: iniciante, intermediário e avançado.

O visual deve transmitir tecnologia, organização e confiança, sem parecer genérico ou exagerado. Quero uma aparência de projeto profissional de portfólio, com cuidado em tipografia, espaçamento, responsividade, contraste e experiência de leitura.
